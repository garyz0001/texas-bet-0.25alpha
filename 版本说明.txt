本版改动
--------
  [修复] 滑条（进度条）取值没有吸附到大盲整数倍
    · 先做了对照诊断：把「本地模式」和「房间模式」渲染出的下注面板
      HTML 逐字节对比，结果完全一致 —— 说明不是两套逻辑，是同一份代码。
      真正的原因：滑条是「按剩余筹码百分比」换算的，
        value = 已投 + 百分比 × 后手
      当后手正好是整百（1000）时，每 1% = 10 = 大盲，看起来全是整数倍；
      一旦后手不是整百（下过盲注后的 995 / 990 / 打过几手的零头），
        1% = 9.95 / 9.9，拖出来的自然就不是大盲倍数。
    · 修复：滑条取值统一吸附
        - 0%  → 保留真实「跟注/过牌额」
        - 100% → 保留真实「后手」（全下，不吸附）
        - 中间档 → 四舍五入到最近的大盲整数倍
      手输数字框仍然保留精确值，方便微调。
    · 本地模式与房间模式共用这段代码，修一处两边都好。

  [修复] 上传到 GitHub Pages 后开房间报「连不上服务器」
    · 根因：GitHub Pages 是纯静态托管，跑不了 Node 后端，
      /api/* 全部返回 404 HTML，前端解析 JSON 失败就落到通用错误文案上。
      这是平台限制，不是代码 bug，但提示文案确实在误导。
    · 修复：
        1. api() 现在按响应 Content-Type 分类错误
             NO_API   = 静态托管，没有后端
             NETWORK  = 后端没起 / 连不上
        2. 首页启动时探测 /api/ping，静态托管时直接在首页说明：
             「这里没有房间后端（当前是纯静态托管，如 GitHub Pages）
               → 房间功能不可用，本地单机可以正常玩。
               开房间的部署方法见 版本说明.txt」
             只有确认是静态托管才这么说；网络抖动不会误报。
        3. 新增 GET /api/ping，返回 {ok, app, ver}
        4. serve.js 下发 Access-Control-Allow-Origin: * 并处理 OPTIONS，
           支持「网页在 GitHub Pages、后端在别处」的分开放法
        5. 新增 config.js：window.TEXAS_BET_API 填后端地址，留空 = 同源
        6. 新增 package.json / render.yaml / README.md，可一键部署后端

GitHub Pages 怎么办
--------------------
  GitHub Pages 跑不了 Node，房间功能在那上面用不了（本地单机可以）。
  三个办法，见 README.md：
    A. 整个目录部署到 Render（仓库里已带 render.yaml，连上即可）
    B. 部署到任意能跑 npm start 的主机
    C. 网页留 GitHub Pages，后端单独部署，然后在 config.js 里填后端地址

启动
----
  双击 启动服务器.bat
  本机 http://localhost:8080
  手机 http://<电脑IP>:8080

2026-10-06 第二轮（同为 0.25alpha）：修 Cloudflare 构建失败 + 补上 Cloudflare 后端
------------------------------------------------

  [原因] Cloudflare Pages 构建失败
         日志里是 `npm error Missing script: "build"`。
         Cloudflare Pages 默认执行 `npm run build`，而项目里没有 build 脚本。
         → 新增 tools/build.js + package.json 的 build 脚本，
           把 index.html/style.css/app.js/engine.js/config.js 复制到 public/。
         `npm run build` 现在可以跑通。

  [但是] Cloudflare Pages 也是纯静态托管，跑不了 Node 后端 —— 和 GitHub
         Pages 一样，房间功能在那上面用不了。所以顺手把后端也搬到
         Cloudflare 上，让房间功能在 Cloudflare 真正可用。

  [新增] room-core.js —— 平台无关的房间逻辑核心
         把原来 serve.js 里的房间代码整体抽出来，只依赖一个 engine 对象
         和一个 Map(rooms)，不碰任何 Node 专有 API。
         serve.js（本地）和 worker.mjs（Cloudflare）共用这一份，
         两边规则 100% 一致，不会出现「本地和线上行为不同」。
         另外 token 改用 globalThis.crypto.getRandomValues（Worker 里没有
         require('crypto')），并加了 route() 路由 + sweep() 回收。

  [重写] serve.js —— 只剩「静态文件 + 把 /api/* 转给 room-core」，
         对外导出 createServer / rooms / core / VER，测试脚本不受影响。

  [新增] worker.mjs —— Cloudflare Worker 版
         · /api/* → Durable Object RoomStore
         · 其它路径 → 静态资源（env.ASSETS）
         · OPTIONS 预检与所有 API 响应都带 CORS
         · RoomStore 是单例 DO，每个请求在同一条线程里串行执行 ——
           和本地 Node 版一样，天然没有并发写冲突
         · 房间状态写入 DO storage：DO 被回收后重建，房间和牌局都还在
         · history（撤销快照）不落盘，避免撑爆存储；撤销只在本手内有意义

  [新增] wrangler.toml —— 静态资源目录 + Durable Object 绑定 + 迁移
  [新增] test-worker.js —— 在 Node 里跑真实 worker.mjs + 模拟 DO storage，
         8 组断言：路由/CORS/建房/加入/房主权限/轮到才能操作/
                   摊牌确认/下一手/DO 持久化/rev 去重/房间回收
  [改]   package.json —— 增加 build / deploy / dev 三个脚本
  [改]   check-ui.js —— 服务端断言改为扫 serve.js+room-core.js+worker.mjs，
         并新增「部署文件齐全」「有 build 脚本」「wrangler 已绑 DO」检查
  [改]   README.md —— 补 Cloudflare 部署步骤（CLI 与 Git 两种）

Cloudflare 部署
---------------
  npm run build && npx wrangler login && npm run deploy
  （或者在 Cloudflare 后台连 Git：build = npm run build，
    deploy = npx wrangler deploy）

  只想用 Pages（纯静态、无房间功能）：build = npm run build，
  output directory = public。构建能过，但开房间会提示没有后端。
